
❯  can you explain how the splines/knots are used as part of the controls?  what 
   does having more or fewer control points on the spline do?  what do the       
  values of each spline control point affect?                                    
                                             
● How splines fit in the pipeline                                                
                                                             
  For each pixel on the cube map, every control field produces a noise value v ∈ 
  [0, Amp]. That value is fed through the field's spline, and the spline's output
   is added to the heightmap:
                                                                                 
  height(pixel) = Σᵢ EvalSpline(field[i].Spline, fbm[i](pixel))
              then normalized to [0,1]         

  The normalized heightmap then drives craters, ocean cutoff, snow line, and     
  (with BiomeTable) per-pixel color lookup. So the spline is the transfer 
  function between "raw noise" and "what that field contributes to terrain       
  elevation."                        
                                               
  What a knot is                                                                 
  
  A knot is one (Input, Output) point on the curve.                              
                                     
  - Input = a value the noise field can produce. Typical range is [0, Amp].      
  - Output = the height contribution at that input.
                                                                                 
  Between knots, the curve is interpolated as a Fritsch-Carlson monotone cubic   
  Hermite spline: smooth (C¹ continuous), and guaranteed never to overshoot if
  the knots are monotone. Inputs outside the first/last knot clamp to the        
  boundary's Output (no extrapolation).

  The curve's steepness between adjacent knots controls how sharp the corresponding terrain transition is. Knots close together in Input with a big Output gap = cliff. Knots spread out with the same Output = plateau.
                                     
  What each control point affects, by field
   
The five fields all share the same spline mechanism but the spline has very different conventional shapes per field:

Continentalness — macro land/ocean. Classic shape:

 [{0, 0.0},        ← deep ocean
  {0.4, 0.05},     ← shallow continental shelf
  {0.5, 0.45},     ← coastline (steep!)
  {0.7, 0.55},
  {1.0, 0.6}]      ← inland plateau
The narrow Input gap from 0.4→0.5 with a big Output jump 0.05→0.45 is what creates a sharp coastline instead of a muddy gradient.
                                                                                 
Erosion — smooths highlands. Typically the spline outputs negative values,     
subtracting from height in already-high regions:                               
                                               
[{0, 0.0}, {0.5, -0.1}, {1.0, -0.25}]                                          
                                                                                 
PeaksValleys — fine roughness. Spline often outputs ~0 most of the range with a spike at one end to add localized mountains.
                                                                                 
 Temperature, Humidity — usually drive the BiomeTable, not the heightmap. If you only want them feeding biomes, give them an empty Spline (Knots: nil) and they contribute nothing to height. The current defaultSpline adds a small ramp — fine for now, but T15 will likely zero T/H out so they don't accidentally bias terrain.

  Practical tuning loop                                                          

1. Set a field's Amp and Freq first to get the noise pattern visible.          
2. Then design the spline as a gameplay decision: where do you want flat regions? Where do you want cliffs?
3. Use 2 knots until you see something to shape; only add knots where you actually want a bend.
4. Watch the cube cross — sharp Output jumps within a tight Input window read as visible cliffs/coastlines on the planet.

The current defaultSpline everywhere is just a placeholder so the new pipeline activates; T15 is where these per-field curves get designed for each archetype.


❯ do we have a setting in a later phase that adjusts the water/land split or changes the ocean height?  or is that also a feature of the Continentalness 

There are two ways to shift the water/land split. They interact, but they pull 
different levers:                                                              

1. profile.OceanLevel (the existing control)                                   

Set on PlanetProfile. It's the post-normalization elevation cutoff: any pixel where the final normalized height h < OceanLevel gets painted as ocean (rocky.go:145). It does not change the heightmap — only how the colorizer interprets it. Raising it floods more of the surface; lowering it exposes more land. Terran's is 0.50. There's no "OceanLevel slider" yet — to tune it interactively you'd edit the JSON or add a numeric input to the explorer.

2. Continentalness spline (the new control)                                    

This shifts where land exists in the heightmap before the cutoff is applied. If your continentalness spline puts most of its output in a low band (e.g. flat at 0.0–0.1 for Inputs 0→0.5, then steep rise), most pixels will fall below     OceanLevel and be ocean. If you flatten the curve high, almost everything lifts above the cutoff and the planet looks dry.

A subtle gotcha

OceanLevel is in post-normalization [0,1] space. The new pipeline normalizes the summed spline outputs across the whole planet, so changing one field's spline rescales every other field's relative contribution. That can shift the effective water line even if you didn't touch OceanLevel. Easiest to think of continentalness as "where is land probable" and OceanLevel as "below what fraction is sea" — and tune them together rather than treating them as independent.

Future phases
 
The master plan doesn't have a dedicated "ocean phase" beyond what's already wired (the existing OceanLevel + OceanColor + the depth-shading you see in rocky.go:145–147). Phase 2 candidates that would affect the water/land feel — wave/foam textures, coastal blending, true bathymetry shading — aren't on the planned task list. If you want any of those, they'd be a new phase. For now: tune water coverage with OceanLevel; tune coastline character with    
Continentalness spline.

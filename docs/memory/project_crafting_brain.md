**Key game mechanics learned:** facility types = production/personal/faction/infrastructure; only **production** matters here. A **production facility makes exactly ONE recipe** (bound recipe_id) — that's WHY crafting is distributed. Level/tier multiplies output: `output × 3^(level-1)`. **Public** facilities (incl other factions') are craft-for-hire for a fee. Hand-craftable recipes (not facility_only) can be made at any docked station.

**A2 decisions (current):**
- **Expander is NOT a tree walk** — topological order over the recipe graph, so shared intermediates aggregate demand BEFORE rounding (3 parents × 4 units of a 3/run recipe = 4 runs, not 6). Rounding surplus + secondary `recipe_outputs` flow back into the on-hand pool for later items. Cycles (refine A→B, recycle B→A) broken via Kahn + recorded in diagnostics. One pass, no fixpoint: recipe choice at X depends only on X's demand, which comes only from X's ancestors.
- **Subtract early, emit haul nodes** when stock is at the wrong base.
- **Hand vs facility = COST vs TIME, not skills.** Hand = `recipes.crafting_time` (fixed). Facility = `production.ticks_per_run` (much faster; level triples throughput). Prefer hand UNLESS `runs×crafting_time + plan_time_so_far > --max-hand-ticks` (default 360 ≈ 1h) AND a facility is known → then cheapest by `fee×runs`, tie-break lower `ticks_per_run`. Threshold blown but no facility → hand anyway, tagged `slow`.
- **Facility speed is NOT derivable** — `crafting_time ÷ ticks_per_run ÷ 3^(level-1)` takes ≥5 distinct values across the 247 observed facilities (6.5×198, 5.0×29, 5.75×7, ~1.44×8, …). **Read `ticks_per_run`/`output_per_run`/`rental_fee_per_run`/`backlog_ticks` per-instance from `details_json`.** Never estimate.
- **Siting**: cheapest `rental_fee_per_run × runs`, tie-break lower `ticks_per_run`, then facility_id. *Accepted trade-off:* fee-only, ignores haul cost → plan prints total haul distance so the operator catches a cheap-but-distant site at review.
- **Dead ends**: facility_only + no known facility → `pkg/finditem` **buy node**; unbuyable → BLOCKED (rest of DAG intact). **BLOCKED = unknown, not impossible** — footer prints catalog coverage.
- **Mine-vs-buy = USER CHOICE per plan** (unchanged): raw leaves carry both options; user tags at review. Not autonomous.
- **Output = canonical JSON step-DAG** (unchanged). `kind ∈ {mine,buy,haul,craft,blocked}`, `status ∈ {ok,blocked,stale,slow}`. Review-first, not an auto-dispatcher.
- Staleness is per-node: holdings older than `--max-stock-age` (24h) still subtract but tag `stale`; unswept facilities sited but flagged.

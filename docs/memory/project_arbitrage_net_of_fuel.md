## play_as find_arbitrage / claim_arbitrage / release_arbitrage — MERGED to local main 2026-07-15 ✅ (merge `f670657`, --no-ff; NOT pushed, NOT deployed — operator REPL, no fleet change)
Built via SDD (brainstorm→spec→plan→2 tasks + hygiene-test commit; opus whole-branch review Ready-to-merge Yes). Operator surface over the hauler arbitrage scanner so a human can take an opp and the fleet won't (haulers select `status="available"`; a claim flips status→claimed and auto-excludes it). All logic in `cmd/tools/play_as/arbitrage_cmd.go` (+`arbitrage_cmd_test.go`); dispatch cases + help in main.go. NO server/schema/persistence change.
- **`find_arbitrage <dest> [--detour N=3] [--limit N=10]`** — reads `globalMarketCollector.GetOpportunities(ctx,"available",300)` (NO fresh scan — operator's choice), builds graph from globalKB systems+connections, `baseline=BFS(cur→dest)`, per-opp `detour=(cur→buy)+(buy→sell)+(sell→dest)−baseline` (clamped ≥0), keeps `detour≤budget`, ranks by **marginal net-of-fuel** `net=GrossProfit − detourJumps×fuelPerJump×priceOf(FromStationID)` desc (tie-break detour asc, id asc). Fuel prices the DETOUR jumps only (marginal cost of the side-trip). `priceOf`/degradation mirror B's `buildPriceOf` (free-pump grand_exchange_station→0 / captured all-in / MedianStationFuelAllIn / else 0 → net==gross). Pure `rankDetourArbitrage(...)` is unit-tested; handler does impure resolve/probe/render.
- **`claim_arbitrage <id>` / `release_arbitrage <id>`** — thin wrappers: `ClaimOpportunity`/`ReleaseOpportunity(ctx, id, globalAgentID)`; store enforces agent-id match on release. `<id>` parses as int.
- Spec: `docs/superpowers/specs/2026-07-15-find-arbitrage-design.md`; plan: `docs/superpowers/plans/2026-07-15-find-arbitrage.md`. Worktree removed, branch `feat/find-arbitrage` deleted.
- **POST-MERGE FIX 2026-07-15 (`b554a16`, UNPUSHED): near-endpoint gate.** Live test (Haven→Nexus Prime, 21j) exposed that detour-total is a poor "actionable" proxy: a haul in a cul-de-sac sitting near the cur→dest geodesic (Sol/Alpha Centauri — ~4j perpendicular but a tight Haven→Sol→Nexus triangle, sol has only 2 neighbors) scores +3 detour yet buys 13j out / sells 10j from dest → list flooded with unreachable far hauls. NO graph bug (BFS matched server's 21; my Haven→Nexus is a legit alternate geodesic). Fix: **near-endpoint gate** = keep opp only if `cur→buy ≤ near` OR `sell→dest ≤ near` (`--near N` default 3, `-1` disables), on top of detour cap; every row now shows `buy@X (Nj out) → sell@Y (Mj to dest)`. `rankDetourArbitrage` gained a `near int` param + `arbRow.BuyOut/SellToDest`. **Haulers UNAFFECTED** — separate ranker (`worker.RankHaulOpportunities`), no detour-from-dest concept.
- **FUTURE — "scenic route" mode (deferred, user-noted 2026-07-15):** accept mid-route hauls within ±N of the TRAVELED PATH (path-relative, not endpoint-relative) — the high-value on-geodesic hauls the near gate drops are still worth taking with a side-trip. Different metric than the endpoint gate.
- FUTURE (spec'd, not built): `--scan`/staleness-hybrid; `my_arbitrage` (list own claims); cargo/affordability sizing; autopilot buy→sell→dest handoff.

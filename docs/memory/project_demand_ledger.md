Feature to track market buy-order demand (esp. NPC Station Manager orders) across systems, since the player market floor-priced everything. BUILT & merged to main 2026-05-29 (da833c8), SIMPLIFIED & merged 2026-05-30 (merge 03d8c93), then HISTORY+FRESHNESS phase merged 2026-05-30 (merge dbba7bb). Tables `market_buy_orders` (live) + `market_demand_history` (time series) + `demand` / `demand history` commands in play_as.

**2026-07-18 LIVENESS-GATE FIX (`391e8b0`, local main, NOT pushed) + `--item` filter (`492815c`):** `LoadCurrentBuyOrders` took `MAX(captured_at)` per (station,item) — which returns the last time an order was EVER seen, so a buy order that VANISHED from a station's book kept surfacing with a multi-hour-stale timestamp; those dead rows were often the highest-value ones and made the whole report read "stale" even though market.db was seconds-fresh (marketbots healthy, 34/34 stations captured <15min; war_citadel's snapshot 5s old but its purified_water rung — gone by then — still showed from a 3h capture with 0 rows in the current snapshot). Fix: added a `station_latest` CTE (MAX per station across ALL items, NOT item-filtered) and gate `datetime(l.mx) >= datetime(sl.smx,'-5 minutes')` — keep a (station,item) only if its latest capture is within one cycle (5min < ~10min marketbot cadence, > few-sec intra-capture write stagger) of the station's newest capture, i.e. the item is in the current snapshot. **Both sides MUST go through datetime()** — raw ISO "…Z" strings vs SQLite's space-form output rank 'T'(0x54) above ' '(0x20) and defeat the gate (same class as the [[project_scanner_outage_expiry_fix]] julianday trap). Rarely-captured stations (pirate bases off the rotation, e.g. voss_redoubt) still surface their latest-known book (low value, flagged STALE >24h). Validated the exact query vs live market.db + unit test (vanished "nickel" rung dropped). **If you ever write a similar current-state query over market_orders (sell side, arbitrage), per-(station,item) MAX has this same resurrect-dead-orders trap — gate against the station's latest capture.** `--item` (`492815c`) pushes item_id into the per-item CTE + outer filter (station_latest stays unfiltered).

**2026-07-17 SOURCE SWAP (`f6074e8`, local main, NOT pushed):** the play_as `demand` REPORT no longer reads knowledge.db `market_buy_orders` — it reads **market.db** via `Collector.LoadCurrentBuyOrders` (pkg/market/demand.go): latest capture per (station,item), buy side, price>0/qty>0, joined to stations/items, adapted 1:1 onto `knowledge.MarketBuyOrderRow` so buildDemandReport + the STN/PLR classifier are untouched. Needs `--market-db-path` (errors if globalMarketCollector nil). Performance depends on partial index `idx_orders_buy_station_item_cap` (schema.sql, `WHERE side='buy'`) — 97s→~4s on the 40M-row live DB; index applied on every Open via IF NOT EXISTS and already built on live data/market.db. Live-smoked as engineer-2: rows 77–86t (~13 min) fresh vs the old ledger's days-stale rows. The knowledge.db capture path (`captureMarket`, market_buy_orders/history tables, `demand history` command) is UNCHANGED and still writes — only the current-demand report moved. Key facts (VERIFIED against data/game-api/*/view_market.json captures):
- `view_market` is station-local; no galaxy-wide buy-order search. Tracking = capture-as-you-visit + persist.
- The COMPACT `view_market` (no item_id, = GetListings) ALREADY returns complete `buy_orders` per item (sum(order.qty)==buy_quantity, never truncated) WITH `source` — `"station"` (Station Manager) or null→`""`. There is no `"player"` value. Per-item deep `view_market(item_id)` calls add NOTHING (user-confirmed). So the original `demand scan` deep-iteration was pointless and was REMOVED; the compact summary table `market_buy_demand` was dropped (migration #37).
- Faction storage CAN be polled remotely via `ViewFactionStorageAt` — that's the phase-2 piece (not built).

Current design (post-simplification):
- ONE table `market_buy_orders` (migrations: created #36, summary table dropped #37). Methods on `*SQLiteKB` only (NOT the `Base` interface — mirrors `faction_orders`); play_as type-asserts `globalKB.(*knowledge.SQLiteKB)`.
- `captureDemand` parses every item's `buy_orders` (with source) from the compact response and does `ReplaceStationBuyOrders` (delete-all-for-station + bulk insert) — fresh snapshot + prunes vanished demand. Hooked into view_market (full, non-category only — `--category`/`item_id` guarded), sellable, dock. Zero extra API calls.
- `demand` command: report classifies STN / PLR>SM / PLR (no more `?`); fulfill-now (cargo+current storage) + craftable-to-fulfill (craftplan direct). Reuses `sellable` fill concept + `craftplan` engine.

Migration **44** `add_market_sell_supply_tables` → `market_sell_orders` (current, replace-per-station) + `market_supply_history` (hourly buckets). NOTE: supply "best price" = LOWEST (cheapest) sell price, the inverse of demand's highest. Regenerate initialize_database.sql after migration.

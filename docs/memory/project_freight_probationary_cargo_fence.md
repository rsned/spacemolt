**What it does:** selection-only change in `pkg/worker/freight.go`. Two pure helpers after `effectiveFreightFloor`: `carrierTierAboveProbationary(tier)` (empty/unknown→false; probationary→false; licensed/trusted/prime→true) and `freightBandExcluded(carrierTier, contractBand, bootstrapEnabled)` = `bootstrapEnabled && contractBand=="probationary" && carrierTierAboveProbationary(carrierTier)`. One filter as the FIRST stmt in `freightCandidate`'s `for _, l := range board.Shipments` loop (freight.go:281, above the liability check): if `freightBandExcluded(prof.Progression.CurrentTier, l.Contract.RiskBand, deps.FreightBootstrap)` → log `"freight: skip %s: probationary cargo reserved for climbing carriers (carrier tier %s)"` + continue. Gated on existing `FreightBootstrap` (reused — no new flag/field/server call). `l.Contract.RiskBand` is the contract's required carrier tier (probationary|licensed|trusted|prime|unpriced), already in the board response.

**Why:** the 500 net floor already rejects loss-leader probationary cargo for advanced carriers, but a PROFITABLE probationary contract (net≥500) was still grabbed by whatever carrier reached it first — including agents that already advanced, stealing the scarce hauls probationary agents need to climb. The fence closes that leak. Complementary to [[project_freight_probation_bootstrap]] (the −400 floor that lets probationary agents TAKE loss-leaders); this reserves them.

**Scope decisions (user, during brainstorm):** advanced carriers still work licensed/trusted/prime freight (skip ONLY probationary cargo, not freight entirely); rule applies at the probationary boundary ONLY (no symmetric higher-tier fencing — YAGNI); unknown/empty tier & `unpriced`/empty band never fenced (safe default). MINOR deferred (cosmetic, log-forensics only): fence logs before the `l.Eligible` check, so an advanced carrier seeing a probationary-band AND server-ineligible listing logs "reserved for climbing carriers" instead of "server marked ineligible" — both `continue`, no behavioral impact.

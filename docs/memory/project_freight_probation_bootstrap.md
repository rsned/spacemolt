**(historical context below — the deadlock this solved)**
**Freight "probationary bootstrap" — let workers eat bounded losses on the first deliveries to escape the probationary carrier tier and unlock much better contracts.**

**The problem is a genuine deadlock, and the mission-learn fleet is stuck in it now.** Observed 2026-07-23: all 42 mission-learn workers idle, empty `active_task_id`, ~80k "no acceptable missions on this board" in ~6h, ~1 completion. Dashboard "missions/hr" = 13,438 is CREDITS/hr (24h trailing avg, `cr(a.missions.per_hour)` in AccountingStrip.tsx:35 + pkg/ovdash/accounting.go), NOT a mission count — it decays as the dry spell persists. Freight gate rejections: `freight: skip …: net 16 below floor 500 (reward 100, fuel 84)`, `net -51 below floor 500 (reward 5, fuel 56)`.

**Mechanic (CONFIRMED real, client ALREADY parses it):** Carrier standing = 4-tier ladder **probationary → licensed → trusted → prime** (`server_docs/openapi.20260719.json` CarrierProfile/CarrierTierProgress; parsed in `pkg/game/serverapi/responses_shipping.go` — `Profile CarrierProfile` + `Progression CarrierTierProgress` on shipping responses). Advancement gated on BOTH `RequiredSuccessfulDeliveries` (count) AND `required_delivered_value` (cumulative cr value); server reports `RemainingSuccessfulDeliveries`/`remaining_delivered_value` live — so NO hardcoded "5", ask the server. Tier governs `CarrierCapacity`: `active_contract_limit`, `single_package_liability_limit`, `aggregate_liability_limit`. **Probationary = capped to small/low-liability contracts** = exactly the 5–100 cr freight the 500-cr net floor rejects → zero deliveries → never advances. The floor (built to stop strand losses, [[reference_trading_missions_not_market_validated]]) is also the lock on the only door out.

**Payoff PROVEN:** fighter-4 payouts jumped ~4x at the next tiers. Bounded loss now → large recurring gain → clearly +EV.

**Design (for the brainstorm):**
- Trigger: `tier == probationary` AND `remaining_successful_deliveries > 0` → relax net floor, accept least-bad small contracts, prefer highest `delivered_value` (advancement needs value, not just count). Resume normal gate once tier flips.
- Loss cap: NOT unlimited — per-mission floor (`net >= -X`) and/or total bootstrap-spend budget per carrier.
- Scope: probationary only, or also nudge licensed→trusted with tighter cap?
- **Per-worker = per-account (NO sharing).** CORRECTION (user, 2026-07-23): "there is no such thing as shared accounts. every credentials.json is a distinct agent." The dedup-by-username trap ([[project_mission_learning_pool]]) is about not DOUBLE-RUNNING one credentials.json in two fleets, NOT multiple agents sharing one account. So each worker owns its carrier standing exclusively → budget Y is cleanly per-worker, NO cross-worker coordination needed. Design confirmed 2026-07-23: loss cap = BOTH per-contract floor (net ≥ −X) AND per-worker/account total bootstrap budget (Y).

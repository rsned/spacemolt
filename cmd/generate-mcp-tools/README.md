# SpaceMolt Generate MCP Tools

> Code generation tool that creates MCP tool definitions from OpenAPI specifications.

## Overview

The generate-mcp-tools tool reads OpenAPI specifications from the SpaceMolt game server and generates Go code containing MCP (Model Context Protocol) tool definitions. This automated code generation ensures that MCP tools stay in sync with the actual API.

## Features

### Core Functionality
- **📖 OpenAPI Parser** - Parses OpenAPI 3.0 specifications
- **🔧 Tool Extraction** - Extracts tool definitions from API endpoints
- **📝 Code Generation** - Generates Go code with tool definitions
- **🎨 Template-Based** - Uses Go templates for customizable output
- **✨ Formatting** - Auto-formats generated code with gofmt

### Processing Features
- **Description Cleaning** - Removes example JSON, keeps first paragraph
- **Type Mapping** - Maps JSON types to MCP schema types
- **Required Fields** - Preserves required field annotations
- **Sorted Output** - Sorts tools alphabetically for stable output

## Quick Start

### Basic Usage

```bash
# Generate tools from default OpenAPI spec
go run ./cmd/generate-mcp-tools

# Generate from custom spec
go run ./cmd/generate-mcp-tools -input custom-openapi.json

# Output to custom location
go run ./cmd/generate-mcp-tools -output cmd/my-tool/tools.go
```

### Building

```bash
# Build the binary
go build -o bin/generate-mcp-tools ./cmd/generate-mcp-tools

# Run the built binary
./bin/generate-mcp-tools
```

## Command-Line Flags

```
-input string
    Path to OpenAPI spec (default "server_docs/openapi.json")

-output string
    Output Go file (default "cmd/mcp-ws-bridge/tools_generated.go")
```

## How It Works

### Process Flow

```
1. Read OpenAPI Spec
   ↓
2. Parse JSON
   ↓
3. Extract Tool Definitions
   ↓
4. Clean Descriptions
   ↓
5. Map JSON Types
   ↓
6. Sort Tools
   ↓
7. Generate Go Code
   ↓
8. Format with gofmt
   ↓
9. Write Output File
```

### Tool Extraction

For each endpoint in the OpenAPI spec:
1. **Path Processing** - Remove leading slash from path
2. **Method Selection** - Prefer POST, fallback to GET
3. **Schema Extraction** - Extract request body schema
4. **Property Mapping** - Map properties to tool parameters
5. **Required Fields** - Preserve required field lists

### Description Cleaning

The tool cleans descriptions by:
1. **Remove Examples** - Strip "**Example:**" and everything after
2. **First Paragraph** - Keep only text up to double newline
3. **Remove Newlines** - Replace newlines with spaces
4. **Collapse Spaces** - Remove duplicate spaces

**Before:**
```
"Claim a registration code for your account

**Example:**
\`\`\`json
{\"code\": \"abc123\"}
\`\`\`"
```

**After:**
```
"Claim a registration code for your account"
```

### Type Mapping

| JSON Type | MCP Schema Type |
|-----------|----------------|
| string | string |
| integer, number | number |
| boolean | boolean |
| array | array |
| object | object |
| (default) | string |

## OpenAPI Schema Requirements

### Expected Structure

```json
{
  "paths": {
    "/endpoint": {
      "post": {
        "operationId": "endpoint",
        "description": "Endpoint description",
        "requestBody": {
          "content": {
            "application/json": {
              "schema": {
                "type": "object",
                "properties": {
                  "param1": {
                    "type": "string",
                    "description": "Parameter description"
                  }
                },
                "required": ["param1"]
              }
            }
          }
        }
      }
    }
  }
}
```

### Supported Features

- **POST and GET methods**
- **Request body with application/json**
- **Nested object properties**
- **Required field arrays**
- **Property descriptions**

### Limitations

- **Query parameters** - Not currently extracted
- **Path parameters** - Not currently extracted
- **Response schemas** - Not extracted
- **Multiple content types** - Only application/json supported
- **Ref schemas** - $ref not resolved

## Integration

### With MCP WebSocket Bridge

The generated code is designed to be used with the MCP WebSocket bridge:

```go
// In cmd/mcp-ws-bridge/main.go
func main() {
	tools := GeneratedTools()
	// Use tools with MCP server...
}
```

### Build Process

Add to your Makefile or build script:

```makefile
.PHONY: generate-tools
generate-tools:
	go run ./cmd/generate-mcp-tools

.PHONY: build-mcp-bridge
build-mcp-bridge: generate-tools
	go build -o bin/mcp-ws-bridge ./cmd/mcp-ws-bridge
```

## Troubleshooting

### Issue: "Error reading OpenAPI spec"

**Cause:** File not found or unreadable.

**Solution:**
1. Verify input file exists
2. Check file permissions
3. Ensure valid JSON format

### Issue: "Error parsing OpenAPI spec"

**Cause:** Invalid JSON or unexpected schema format.

**Solution:**
1. Validate JSON with online validator
2. Check spec version compatibility
3. Review spec structure

### Issue: "Formatting Go code"

**Cause:** Generated code has syntax errors or formatting issues.

**Solution:**
1. Check tools_generated.go.unformatted for debugging
2. Review template syntax
3. Verify type mappings are correct

### Issue: "No tools generated"

**Cause:** OpenAPI spec has no extractable endpoints.

**Solution:**
1. Verify paths exist in spec
2. Check for POST/GET methods
3. Ensure request bodies exist

### Issue: "Description too long"

**Cause:** Descriptions not being cleaned properly.

**Solution:**
1. Check description format in spec
2. Modify cleanDescription() function
3. Add custom cleaning logic

## Best Practices

### Development Workflow

```bash
# 1. Update OpenAPI specs
go run ./cmd/update-server-docs

# 2. Regenerate tools
go run ./cmd/generate-mcp-tools

# 3. Review changes
git diff cmd/mcp-ws-bridge/tools_generated.go

# 4. Rebuild
go build ./cmd/mcp-ws-bridge

# 5. Test
./bin/mcp-ws-bridge
```

### Version Control

The generated file should be committed to version control:
- Allows tracking API changes
- Enables code review
- Provides rollback capability

### Customization

To customize generation:
1. Modify `toolsTemplate` in main.go
2. Adjust type mappings in `mapJSONType()`
3. Update description cleaning in `cleanDescription()`
